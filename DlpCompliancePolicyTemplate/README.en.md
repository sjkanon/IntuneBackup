## What is in it, and where it comes from

| Sensitive information type | Confidence | "Few" | "Bulk" |
|---|---|---|---|
| Netherlands Citizen's Service (BSN) Number | High | 1–4 | 5+ |
| Netherlands Passport Number | Medium | 1–9 | 10+ |
| Netherlands Driver's License Number | Medium | 1–9 | 10+ |
| Netherlands Tax Identification Number | High | 1–9 | 10+ |
| Belgium National Number | Medium | 1–4 | 5+ |
| Belgium Passport Number | Medium | 1–9 | 10+ |
| Belgium Driver's License Number | Medium | 1–9 | 10+ |
| Credit Card Number | High | 1–9 | 10+ |
| EU Debit Card Number | High | 1–9 | 10+ |
| International Banking Account Number (IBAN) | High | — | 20+ |

- **Microsoft's structure.** Every built-in financial or privacy template in Purview has a rule
  for 1–9 matches (notify) and one for 10+ (block and report), both on "shared outside the
  organisation". There is no Dutch or Belgian template; those types only occur in *GDPR Enhanced*,
  together with 27 EU address types and trainable classifiers — far too noisy for a small company.
- **`maxcount -1` instead of Microsoft's 500**, as in
  [kingsrule50/m365-purview-data-protection](https://github.com/kingsrule50/m365-purview-data-protection):
  otherwise a file with 501 card numbers misses the bulk rule.
- **Confidence from each type's definition.** A BSN is only recognised with its checksum *and* a
  keyword such as *bsn* or *burgerservicenummer*; passport and driver's license reach Medium at
  most, so High would never fire. An IBAN is High on its checksum alone — every invoice has one —
  so IBAN only counts in bulk (a payroll or SEPA export). The VAT number (and the Belgian
  enterprise number) is left out on purpose: it is on every invoice by law.
- **All three Belgian types reach Medium at most.** The national number is only Medium with its
  checksum *and* a keyword (*identiteitskaart*, *numéro national*, *national number* …); the checksum
  alone gives Low, which is too loose for a number that starts with a date of birth. Note:
  *rijksregisternummer* itself is not in Microsoft's keyword list, so a Flemish document that only
  uses that word is not recognised.
- **BSN is bulk from 5 already**: the Dutch Data Protection Authority treats the BSN more strictly
  than the other numbers. The Belgian **national number** gets the same threshold: in Belgium it is
  also the tax and social security number, so it is the one that opens everything.
- **Belgian tips are bilingual** (nl / fr): Belgian tenants have both language groups. The
  Financial tips are Dutch only.

Not found: a public repo, by an MVP or anyone else, that deploys DLP with Dutch or Belgian types. The
structure is Microsoft's, the thresholds are explained above.

## Deploying on their own

1. CIPP → **Tools → Community Repos** → this repo → the file → **Import** (or the regular
   template sync: these files carry a `RowKey` and are written directly).
2. **Security → Compliance → DLP Templates** → the template → **Deploy**.

So a tenant without the baseline can get just the Notify policies.
